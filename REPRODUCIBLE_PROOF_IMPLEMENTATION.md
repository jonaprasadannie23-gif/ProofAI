## Summary

Added a "Reproducible Proof" section that displays a complete, standalone Python script users can copy and run independently to verify ProofAI's answers.

## How the Reproducible Script is Constructed

### Input
- `generated_code`: The short LLM-generated analysis code (e.g., `result = df["sales"].sum()`)
- `filename`: The actual uploaded filename (e.g., `"sales.csv"`)

### Output Template

```python
#!/usr/bin/env python3
"""
Reproducible Proof Script
Generated by ProofAI

This script reproduces the analysis result independently.
Run it with the uploaded dataset to verify the answer.
"""

import pandas as pd
import numpy as np

# Load the dataset
df = pd.read_csv("actual_filename.csv")  # or pd.read_excel() for .xlsx

# Execute the analysis
{generated_code}

# Display the result
print("Result:", result)
```

### File Extension Handling

- `.csv` → `pd.read_csv("filename.csv")`
- `.xlsx`, `.xls` → `pd.read_excel("filename.xlsx")`
- Unknown → defaults to `pd.read_csv()`

## Design Rationale

### Why Two Separate Sections?

1. **Generated Python Code**
   - Shows what the AI generated
   - Short, focused on the core logic
   - Educational value (shows the analysis strategy)

2. **Reproducible Proof**
   - Complete, runnable script
   - Satisfies reproducibility requirement
   - Users can verify independently
   - Can be shared with collaborators

### Why Not Combine Them?

Combining them would make the "Generated Python Code" section longer and less readable. The current approach:
- Preserves the clean, short generated code display
- Adds reproducibility without cluttering the main answer
- Allows users to copy just the core logic OR the full script

### Why Collapsed by Default?

The "Reproducible Proof" section is collapsed by default because:
- Most users care about the answer first
- Power users can expand it when needed
- Reduces visual clutter
- Consistent with other collapsible sections
